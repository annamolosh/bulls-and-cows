# Анализ сложности алгоритмов (Big O)

## 1. generateSecret(length, base)

**Временная сложность: O(n × b)**

- `slice()` создаёт строку из `base` символов — O(b).
- `split("")` преобразует строку в массив — O(b).
- Цикл выполняется `length` раз.
- `Math.random()`, `Math.floor()` и получение элемента массива по индексу выполняются за O(1).
- Конкатенация строк `secret += digit` может занимать до O(n) на итерацию.
- `splice()` удаляет выбранный элемент и может сдвигать остальные элементы массива — O(b).

Общая сложность: O(b + n × b + n²). Поскольку n ≤ b, итоговая временная сложность — O(n × b).

**Пространственная сложность: O(b)**

- `availableDigits` хранит до `b` символов.
- `secret` хранит `n` символов.
- Поскольку n ≤ b, итоговая пространственная сложность — O(b).



## 2. evaluateGuess(secret, guess)

**Временная сложность: O(n²)**

- `toLowerCase()` и `split("")` обрабатывают строки длиной n — O(n).
- `map()` проходит по всем цифрам попытки — O(n).
- `filter()` для поиска быков проходит по массиву — O(n).
- `filter()` для поиска совпадающих цифр также проходит по массиву.
- Внутри второго `filter()` вызывается `includes()`, который в худшем случае проверяет до n элементов — O(n).
- Поэтому сочетание `filter()` и `includes()` даёт O(n²).
- Вычитание при подсчёте коров выполняется за O(1).

Итоговая временная сложность — O(n²).

**Пространственная сложность: O(n)**

- Создаются массивы `normalizedSecret` и `normalizedGuess`.
- Дополнительно создаются массивы `comparisons`, `matchingPositions` и `matchingDigits`.
- Каждый из них содержит не более n элементов.

Итоговая пространственная сложность — O(n).



## 3. createDigitValidator(base)

**Временная сложность:**

- slice(0, base) создаёт строку допустимых цифр длиной до base — O(b).
- Создание внутренней функции validateDigit — O(1).
- При вызове validateDigit метод toLowerCase() для одного символа занимает O(1).
- Проверка длины символа — O(1).
- includes() в худшем случае проверяет до b символов — O(b).

Итого:
- Создание валидатора — O(b).
- Одна проверка символа — O(b).
- Пространственная сложность: O(b)
- Строка allowedDigits хранит до b символов.
Внутренняя функция использует эту строку через замыкание.



## 4. isValidGuess(guess, length, base)

**Временная сложность: O(n × b)**

- Проверка длины строки — O(1).
- Создание валидатора через `createDigitValidator(base)` — O(b).
- `split("")` преобразует строку в массив символов — O(n).
- `every()` проходит по n символам.
- Для каждого символа вызывается `isValidDigit()`, внутри которой `includes()` может проверять до b символов — O(b).
- Поэтому проверка всех цифр занимает O(n × b).
- `toLowerCase()` и создание `Set` занимают O(n).
- Проверка размера множества — O(1).

Итоговая временная сложность — O(n × b).

**Пространственная сложность: O(n + b)**

- Массив `digits` занимает O(n).
- Строка `normalizedGuess` и множество `uniqueDigits` занимают O(n).
- Строка `allowedDigits`, созданная валидатором, занимает O(b).

Итоговая пространственная сложность — O(n + b).



## 5. countPossibleSecrets(length, base)

**Временная сложность: O(n)**

- Проверки входных данных выполняются за O(1).
- Создание ключа для кеша и поиск в `Map` занимают O(1) в рамках модели с ограниченными значениями параметров.
- Рекурсивный вызов уменьшает `length` и `base` на единицу.
- Глубина рекурсии не превышает n.
- Каждый результат сохраняется в `Map` с помощью `cache.set()`.
- При повторном вызове с теми же аргументами результат берётся из кеша без повторных вычислений — O(1) в среднем.

Первое вычисление: O(n). Повторное вычисление тех же аргументов: O(1) в среднем.

**Пространственная сложность: O(n)**

- Стек рекурсии занимает O(n).
- При первом вычислении в кеш добавляется до n промежуточных результатов.
- Кеш хранит результаты и после завершения вызова функции. Его общий размер зависит от количества различных пар аргументов, переданных функции за всё время работы приложения.










Если проверяем только первый элемент — O(1).
Константная, время почти не зависит от размера данных

Если проверяем все элементы по очереди — O(n).
Линейная, количество операций растёт вместе с данными

Если для каждого элемента проверяем все остальные — O(n²).
Квадратичная, для каждого элемента проходим по всему массиву

O(log n) Логарифмическая, размер задачи уменьшается в несколько раз

O(2ⁿ) Экспоненциальная, количество операций растёт очень быстро

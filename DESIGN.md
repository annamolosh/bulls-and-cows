# Архитектура проекта Bulls and Cows

## 1. Общая архитектура

Проект представляет собой браузерную игру «Быки и коровы», разработанную на TypeScript.

Архитектура разделена на три основные части:

- **Core** — игровая логика, вычисления и проверки.
- **UI** — создание и обновление пользовательского интерфейса.
- **Services** — вспомогательные сервисы.

Игровая логика отделена от DOM и реализована преимущественно с использованием чистых функций.

## 3. Основные структуры данных

В проекте используются следующие основные типы:

- **GameSettings** — настройки игры: длина секретного числа и система счисления.
- **GameState** — состояние игры: секретное число, настройки, история попыток, статус победы и время начала.
- **GuessResult** — результат проверки попытки: количество быков и коров.
- **HistoryEntry** — запись об одной попытке игрока.

Для хранения истории используется массив объектов `HistoryEntry`.

Для проверки уникальности цифр применяется структура `Set`.

Для кеширования результатов рекурсивных вычислений в `countPossibleSecrets` используется `Map`.

## 4. Алгоритмы и игровая логика

### Генерация секретного числа

Функция `generateSecret(length, base, random)` создаёт секретное число заданной длины в выбранной системе счисления.

Каждая цифра может использоваться только один раз. Генератор принимает функцию случайного числа через параметр `random`, что позволяет использовать контролируемые значения при тестировании.

### Проверка попытки

Функция `evaluateGuess(secret, guess)` сравнивает секретное число с попыткой игрока.

Сначала определяется количество быков — совпадений цифр и их позиций. Затем определяется количество коров — совпадающих цифр, расположенных на других позициях.

### Валидация

Функция `createDigitValidator(base)` возвращает функцию проверки допустимости отдельной цифры для выбранной системы счисления.

Функция `isValidGuess()` проверяет длину попытки, допустимость символов и отсутствие повторяющихся цифр.

### Обновление состояния игры

Функция `submitGuess(state, guess)` обрабатывает игровую попытку.

Она проверяет состояние игры, валидность попытки и отсутствие повторов. Если попытка корректна, вычисляет результат и возвращает новое состояние игры с обновлённой историей.

### История попыток

Функция `addHistoryEntry()` добавляет новую запись в историю, не изменяя исходный массив.

## 5. Принципы функционального программирования

В проекте применяются следующие принципы:

- **Чистые функции.** Основная игровая логика не зависит от DOM и внешнего состояния.
- **Неизменяемость данных.** При обновлении состояния игры и истории создаются новые объекты и массивы.
- **Функции высшего порядка.** Для обработки массивов используются `map()`, `filter()`, `every()` и `some()`.
- **Замыкания и каррирование.** `createDigitValidator(base)` возвращает функцию, использующую переданное основание системы счисления.
- **Инъекция зависимостей.** Генератор принимает функцию случайного числа через параметр `random`, что упрощает тестирование.
- **Мемоизация.** В `countPossibleSecrets()` используется `Map` для сохранения результатов рекурсивных вычислений.

## 6. Принципы Clean Code

При разработке применялись следующие практики:

- Имена функций и переменных отражают их назначение.
- Каждая функция отвечает за конкретную задачу.
- Игровая логика отделена от пользовательского интерфейса.
- Типы данных определены явно с помощью TypeScript.
- Повторная проверка игровой логики вынесена в отдельные функции.
- Для проверки корректности поведения используются автоматические тесты Vitest.

## 7. Тестирование

Для тестирования используется Vitest.

Тесты охватывают генерацию секретного числа, вычисление быков и коров, валидацию, рекурсивный подсчёт возможных комбинаций, работу истории и обработку игровых попыток.

На момент подготовки документа проект содержит 41 автоматический тест.
